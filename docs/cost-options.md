# 省钱的办法：记下来，还没有做

**这里列的办法都没有实现。** 用户定的（2026-11-06）：这一轮正式运行不做省钱改动，只把办法记下来，以后逐项再定。代码、配置模板和预留都还是原样。决定见 [DECISIONS.md](../DECISIONS.md)。

这份文档写的是自己的运行时（`runtime: "own"`）。它在真实 OpenRouter 上只跑过一次付费探测（Q5，2026-11-07，两个很短的回合，不接 QQ），所以下面省多少都是**按价格算出来的估计**，不是测量。写明“实测”的只有那一次样本里的数，其余都是估计。算式照写，方便以后用真实数字重算。

价格按锁定的目录价，每百万 token：Opus 输入 $4、输出 $20、缓存读 $0.2、缓存写（5 分钟）$5，1 小时缓存写 $8；Haiku 输入 $0.1、输出 $0.5。系统提示词：own 的系统块在 own 的 Q5 里实测 4359 token（一次样本；之前估 4350–4400，OpenClaw 路线上 Q5 实测缓存写入 4350）。下面的算式按 4359 算，能重算的结果都按它改了；最后“如果都做了”的合计没有重算。

**直连 Anthropic 时**（新运行时可选，用户 2026-11-07 同意的接口层，见 [DECISIONS.md](../DECISIONS.md) 的“用户定的（2026-11-07，Provider）”）：手抄的价格表和上面这组目录价相同，所以下面的估算照样能套用，但都没有量过，真实 Anthropic 上一次都没有跑过。几处不一样：没有上报的 `usage.cost`，费用只按 token 乘价格表算；没有 Key 读数，也不对账；兜底是声明的工作区月度上限，不是 Key 的日限额，所以下面写到“先碰到 Key 的日限额”的地方，换成这个月度上限，而它拦不住一天花多少。第 9 项 Fast Mode 在直连时是请求里的 `speed` 字段，这一版从不发它，响应显示走了快速模式、或者读不到这一项时，按 2 倍价格算并暂停付费（响应里这个字段的名字没有在真实 API 上确认）。这些办法都没有按直连重新评估过。

## 现在大概花多少

真实记录都来自 OpenClaw 路线：

- Q5：没命中缓存的回合 $0.0248，命中的 $0.0067。
- Q6：18 次真实 @ 共 $0.2382，平均 $0.0132。
- Q7：两次插话 $0.0358、$0.0398。
- 一次判定约 $0.00013–0.00017。

own 的 Q5（实测，一次样本，问题很短，没有群聊上下文）：没命中缓存的回合 $0.0249（输出 140 token，其中思考 51），命中的 $0.0090（输出 366，其中思考 155）。

own 下的估计（系统提示词按实测的 4359 token，输出按 100–150 token；Q5 实测的输出是 140 和 366，比这里多，只有一次样本）：

- 没命中缓存、没有历史：4359 × $5 + 110 × $4 + 150 × $20，每百万 token，约 $0.0252。
- 没命中缓存、上下文满（历史约 2000 token，估计）：0.0218 + 0.008 + 0.003，约 $0.033。
- 命中缓存、上下文满：0.00087 + 0.008 + 0.002，约 $0.011。
- 假设一天 38 次主模型回合（30 次 @ 或点名，8 次插话），一半命中缓存，加上约 $0.06 的判定：19 × 0.0328 + 19 × 0.0117 + 0.06，约 $0.91/天，30 天约 $27。38 次是假设，不是统计。

现在每天先碰到的是 Key 的日限额（示例 $1.60/UTC 日），不是本地的 $2.5。

### 1. 补全用量记录

- **做法：** own 的 `turn_usage` 行多记几样，只记数字和名称，不记正文：prompt token、思考 token、`finish_reason`、服务方名称、距上一次主模型调用的间隔、距这个群上一回合的间隔、带了几条历史。再加一个汇总命令，按天或按周看缓存命中率、间隔分布（不到 5 分钟、5–10、10–60、60 分钟以上）、连续两回合是不是同一个服务方、各类回合的费用。另加一个单元测试，确认系统提示块在不同群、不同回合类型、不同时间下逐字节相同，这样一份缓存能给所有群用。
- **估计省多少：** 直接省 $0。它是第 4、5 项的依据。它还守住共用缓存：系统块没命中约 4359 × $5/M = $0.0218，命中约 4359 × $0.2/M = $0.00087，每回合差约 $0.021（4359 是实测，差价是按目录价算的）。
- **要不要你同意：** 调研认为不需要，因为只多记费用相关的数字，按 `CLAUDE.md` §7.6，日志可以留费用记录，§8.4 也允许记服务方名称。但这一轮正式运行的改动都延后，做之前仍会先问你。
- **风险：** 低。README 的“数据保留”要列出新字段。
- **文件和测试：** `src/clo-plugin/lib/core/turn.js`、`openrouterChat.js`、`log.js`，新的汇总命令；`tests/unit/turn.test.mjs`（新字段有值，同时扫一遍没有正文），新的汇总测试（只用 fixture），`qq-redaction` 一类的检查。

### 2. 她较早的回复在上下文里截短

- **做法：** 上下文里她最新的一条回复照常保留，所以“第二点展开说说”还能用。更早的回复截到约 400 个估算单位（约 200 字），用现有的“…（太长，后面省略）”标出。群友的话不变。这只是同一个有界环里每行的上限更低，40 条、24 小时的规则不变。
- **估计省多少：** 现在单行上限 1500 单位（约 750 字），截到约 200 字，约 550 × 1.156 ≈ 640 token × $4/M ≈ **$0.0025**，只在带着一条这样的旧回复的回合上省。如果同时做第 4 项，单行上限已经降到 750 单位，多省的只有约 (750 − 400) / 1.7 × $4/M ≈ **$0.0008**。都是估计。
- **要不要你同意：** 调研认为不需要，这一轮仍然延后。
- **风险：** 问到她两条以前的回答时，细节可能没了。效果只能用已有的付费样本看，不为改这一项另外花钱。
- **文件和测试：** `src/clo-plugin/lib/core/context.js`；`tests/unit/context-buffer.test.mjs`（同一个测试里：旧回复截到 400，最新回复保留，群友的行不变），`gate-own-runtime.test.mjs` 照样通过。`DECISIONS.md` 里“上下文单行上限”那一行旁边要记一笔。
- **什么时候再决定：** 和第 4 项一起，看过新运行时的 Q6 之后。

### 3. 插话的输出上限降到 1200

- **做法：** 新配置项 `claudeModel.interjectMaxTokens`，默认 1200，校验不低于 1100，比 OpenRouter 文档写的思考预算下限 1024 高。只给插话用，必答回合仍是 3000。
- **估计省多少：** 平时几乎是 $0，OpenClaw 路线上真实回答只有 65–144 token，own 的 Q5 两个回答是 140 和 366（含思考，一次样本）。一次失控的插话最多少花 (3000 − 1200) × $20/M = $0.036。插话的预留从 24000 × $5 + 3000 × $20 = **$0.18** 降到 24000 × $5 + 1200 × $20 = **$0.144**（每百万 token）。
- **要不要你同意：** 要。它改预留大小，`DEPLOYMENT.md` 写着预留和预算还没有按真实数字调整，这归部署者决定。
- **风险：** 如果 OpenRouter 在 effort low 下把思考预算定成 1024，1200 里只剩约 176 token 给回答，约 150 个汉字，比出口截插话的 400 字还短，插话可能被截断。项目里判定模型的思考下限另写了 2000（`models.js`），和这里的 1024 是同一件事的两个数，做的时候要统一成一个常量。
- **文件和测试：** `src/clo-plugin/lib/core/config.js`、`turn.js`、`ledger.js`、`config.example.json`；`tests/unit/turn.test.mjs`（插话发 1200、@ 发 3000，在同一个测试里），`ledger.test.mjs`（插话预留 144000 微美元，必答不变），`config.test.mjs`（1000 拒绝、1200 接受、没写时用 `maxTokens`）。
- **什么时候再决定：** own 的 Q5 在 1200 下量过一次：思考 51 和 155 token，`finish_reason` 都是 stop，没有被截断。这只是两个很短的必答回合，插话回合没有量过，所以等新运行时的 Q6 有更多样本再定。

### 4. 上下文窗口 3000 → 1500

- **做法：** `retention.contextMaxTokens` 从 3000 改成 1500。`contextMaxItems` 仍是 40，1500 时很少到 40 条。更紧的 1200 token、20 条可以作为另一个选项。单行上限跟着变成 max(750, 256) = 750 单位。这是配置值，部署者改 `config.json` 再 `clo apply` 就行，不用改代码；要改的是模板和文档里的默认值。
- **估计省多少：** 调研离线估算，3000 上限下满的历史在用户消息里约 1.7k–2.0k token。这是把估算单位按约 1.7 的比例折成 token 得出的，比例只有两个样本，没有确认；own 的 Q5 没有带历史，也没有量到这一项。减半约省 850–1000 token × $4/M = **$0.0034–0.004** 每回合，命不命中缓存都一样（历史不在缓存里）。按假设的每天 38 回合，约 **$0.13–0.15/天**。1200/20 的选项约 $0.0052/回合，约 $0.20/天。都是估计。
- **要不要你同意：** 要。
- **风险：** 她能回看的对话变短：40 字一行的话，大约能留 18 行，现在约 37 行。“上面那个”指得远一点就接不上。`DECISIONS.md` 里“回合里看不到什么”那一条，正是为了这种情况才留着上下文。回退只要改回配置再 `clo apply`。
- **文件和测试：** `config.example.json`、`README.md`、`docs/group-chat-design.md`；`tests/unit/context-buffer.test.mjs`（1500 下单行上限 750、从新到旧截断；3000 下保留更多行作对照），`gate-context-window`、`gate-own-runtime`、`config` 的测试用示例配置通过。
- **什么时候再决定：** 看过新运行时 Q6 的真实回答之后。

### 5. 1 小时缓存

- **做法：** 系统提示块的缓存标记加 `ttl:'1h'`，配置 `cacheRetention` 多一个只给 own 用的值。1 小时缓存写入价 $8 要锁进 `versions.lock.json` 和 `models.js`，预留和没有用量时的估价都要按 $8 算输入。
- **估计省多少：** 取决于群里说话的间隔。按实测的系统块 4359 token 算（以前按 4350）：
  - 一个群一天 12 次，每次隔 15 分钟：5 分钟缓存每次都没命中，12 × 4359 × $5/M ≈ $0.262；1 小时缓存写一次 4359 × $8/M ≈ $0.0349，再读 11 次 11 × 4359 × $0.2/M ≈ $0.0096，合计约 $0.044。**约省 $0.22/天。**
  - 说话集中在几阵里的一天：两种差不多（约 $0.143 对 $0.136）。
  - 只有一次、前后都没人说话：1 小时缓存反而多花 $0.0349 − $0.0218 ≈ $0.013。
  - 打平的条件：5 分钟缓存没命中的回合里，要有至少 3 / (8 − 0.2) ≈ 38.5% 换成 1 小时缓存后能读到缓存，才不亏。
- **要不要你同意：** 要。它改 `DECISIONS.md` 里“提示缓存只放一个 5 分钟标记”的决定，还要多做一次付费样本（金额另外同意），确认 OpenRouter 对这个模型真的传 `ttl`。
- **风险：** 不做第 6 项的话，必答预留升到 24000 × $8 + 3000 × $20 = $0.252。OpenRouter 的粘性路由 10 分钟后失效，换了服务方要再写一次缓存（约 $0.0349）。Q5 探测现在不按 own 的 $5.5 上限检查 1 小时缓存写入价，理由是它拒绝带 `ttl` 的请求；这个价格仍按一般的主模型上限 $8 检查，高于 $8 就拒绝。探测要是用上 `ttl`，这个例外就要去掉。1 小时缓存在 own 的 Q5 里没有试过。
- **文件和测试：** `turn.js`、`config.js`、`models.js`、`ledger.js`、`gate.js`、`versions.lock.json`、`DECISIONS.md`、`docs/own-runtime.md`；`turn.test.mjs`（只有一个标记，只有选 1 小时时才带 `ttl`），`config.test.mjs`（只有 own 能选），`ledger.test.mjs`（$8 和 $5 两种），`models.test.mjs`（锁价，涨价就拒绝）。
- **什么时候再决定：** 用第 1 项攒一周数据之后。

### 6. 单条消息截断，同时把 `contextTokens` 降到约 12500

- **做法：** 当前这条消息超过约 3200 个估算单位（约 1600 个汉字）时截短并标出，再做输入上限检查，这样贴了长文的 @ 仍能得到回复，而不是 `input_bound`。`claudeModel.contextTokens` 从 24000 降到约 12500。要先确认加起来放得下：系统约 7471 单位 + 历史 1500 + 框架约 300 + 3200 = 12471，所以是 12500，不是 12000。
- **估计省多少：** 平时 $0。现在一条贴进来的长消息能带约 7.6k token（离线估算，按上面那个没有确认的比例折算），多花约 $0.03，截短后约 $0.007。必答预留从 $0.18 降到 12500 × $5 + 3000 × $20 = **$0.1225**；和第 3 项一起，插话预留是 12500 × $5 + 1200 × $20 = **$0.0865**。预留小了，靠近各层上限时能多放几个回合，这只在 Key 日限额高于约 $2.1 时才有意义。都是估计。
- **要不要你同意：** 要，理由同第 3 项。
- **风险：** 很长的消息，模型只看到开头。依赖第 4 项，不然数字放不下。
- **文件和测试：** `turn.js`、`context.js`（导出截短函数）、`config.example.json`；`turn.test.mjs`（8000 字的消息被截短后发出，短消息不变作对照，手工造的超长系统提示仍报 `input_bound`），`ledger.test.mjs` 的预留数字，`models.test.mjs`、`cli-model.test.mjs`、`gate-own-runtime.test.mjs` 里钉住的值。
- **什么时候再决定：** 第 4 项定了之后，有 Q6 的数据再看。

- **文件和测试：** `config.js`、`models.js`、`turn.js`、`ledger.js`、`versions.lock.json`、`persona/group-notice.zh.md`、`README.md`；`models.test.mjs`（只接受 `anthropic/`，没有 fallbacks），`cli-model.test.mjs`（要 `--qq-platform-notified`），`turn.test.mjs`（插话用第二个型号，必答用 Opus 作对照）。

### 8. 减少插话次数

- **做法：** `interject.perDay` 8 → 4，`cooldownMinutes` 8 → 15。可以只改模板默认值，也可以只在 `config.json` 里给某个群改，不用改代码。这些在 `CLAUDE.md` §5.3 里本来就是可调的聊天体验参数；改默认值的话，§5.3 那一行和设计文档跟着改。
- **估计省多少：** own 的插话通常不命中缓存，约 4359 × $5 + 110–1600 × $4 + 150 × $20（每百万 token）≈ $0.025–0.031。每天少 4 次，每个开了插话的群约省 **$0.10–0.12/天**。估计。
- **要不要你同意：** 要。
- **风险：** 她插话少了。@、回复可洛和危险路线不受影响。冷却低于 5 分钟对缓存也没有帮助。
- **文件和测试：** `config.example.json`，`CLAUDE.md` §5.3 的默认值（只在改默认值时），`docs/group-chat-design.md`；`tests/unit/gate-limits.test.mjs`（新默认下当天第 4 次插话通过、第 5 次被拒，冷却中 @ 照常回答，在同一次运行里）。
- **什么时候再决定：** 随时，按你想要的聊天体验定。

### 9. Fast Mode（你提的，只作以后的选项）

- **做法：** 你提到冷启动时可能考虑 Fast Mode：让请求走 `anthropic/fast` 端点，更快。
- **估计多花多少：** 这不是省钱，是多花钱换速度。单价约 2 倍，$8/$40（输入和输出，每百万 token）。一次没命中缓存的 @ 约从 $0.025 变成约 $0.05（估计）。fast 端点上缓存读写的价格没有查。
- **要不要你同意：** 要，这是你的决定。
- **要改的：**
  - 新的价格锁（`versions.lock.json`、`models.js`），`clo model refresh` 的涨价检查要认它。
  - 预留跟着翻倍。比如必答预留现在是 24000 × $5 + 3000 × $20 = $0.18，输入和输出都翻倍就是约 $0.36。
  - Q5 的价格界限要重写。探测现在的上限是 $5.5/$22，fast 的价格高于它；按 $8/$40，光第 1 回合就要 12317 × $8 + 1200 × $40 ≈ $0.147，超过 $0.10。
  - 和现在的假设冲突：探测和文档都假设基础型号不会被路由到 fast 端点。这一点只是读 OpenRouter 路由文档得出的推断，请求里也没有 `provider.max_price`（用户定的）。现在靠的是第 1 回合之后的 `price_above_bound` 检查：报告的费用高于锁定价加 10%，运行就停。用 Fast Mode 就要明确改路由，这个检查也要跟着改。
  - 走 fast 端点算不算模型变更、要不要报平台，没有查。
- **风险：** 每天的花费更早碰到 Key 日限额，碰到之后她就静默或只回失败句。
- **文件和测试：** 价格锁、预留、Q5 探测（`src/tools/q5-probe.mjs`、`tests/unit/q5-probe.test.mjs`）、`turn.js` 的路由字段和它们的测试。
- **什么时候再决定：** own 的 Q6 有了真实数字之后，你再看要不要（Q5 只有两个很短的回合）。

### 10. 直接调低上限

- **做法：** 调低 OpenRouter 上这个 Key 的日限额，或者调低本地的分层上限（插话 $0.75、点名 $2.25、@ $2.5，在 `config.json` 的 `budget` 里）。这是直接限制总花费，不改代码。
- **估计省多少：** 上限是多少，一天最多就花多少。比如 Key 日限额从示例的 $1.60 调到 $1.00，一天最多 $1.00，30 天约 $30。
- **要不要你同意：** Key 限额只有你能在 OpenRouter 上设；本地上限也由你改。
- **风险：** 碰到上限后插话先停，然后点名，最后 @ 只收到失败句。`budget.keyDailyLimitUsd` 要和 Key 上的实际限额相同，不同时 `clo mode live` 报 `key_limit` 拒绝。
- **文件和测试：** 只有 `config.json` 和 OpenRouter 上的设置。限额比对已经有测试。
- **什么时候再决定：** 随时。

## 排除的办法

| 办法 | 为什么不做 |
|---|---|
| 落盘或跨重启的摘要、压缩 | 违反“正文不落盘，重启丢失”（`CLAUDE.md` §5.4），也违反她的回复只放内存的决定。这一版也没有长期记忆。只有你能放宽这些规则，放宽要记进 `DECISIONS.md` |
| 只放内存的滚动摘要（用 Haiku 压缩旧的行） | 摘要被挤出的行，违反“先到者截断”。只摘要窗口里的行，约省 1350 × $4/M − (1500 × $0.1 + 150 × $0.5)/M ≈ $0.0052 每回合（估计），和第 4 项缩小窗口一样多，而第 4 项不用花钱。它还多一条把群友的话发给第三方的路径，要改告知（D5），也没有预算层；模型转述真实的人，可能张冠李戴或编出细节 |
| 在历史上加第二个缓存断点 | 现在的消息布局做不到：带时间的框架行在最前面，挤出从前面开始，显示名一变标签就重写。要改防注入的框架和“只放一个 5 分钟标记”的决定。约省 $0.0065 每个同群热回合，做了第 4 项后约 $0.0023（估计）。只有第 1 项显示同群连续说话很多、又没做第 4 项时，才再看 |
| 保活请求，维持 5 分钟缓存 | 每天约 320 次 × $0.00087 ≈ $0.28（估计），比 1 小时缓存还贵，而且是没人要的调用 |
| 主模型 effort 设成 `none` | 思考是强制的，`models.js` 拒绝 `none`，OpenRouter 会返回 400。effort low 的思考：OpenClaw 路线的直连实测 0–25 token，own 的 Q5 两回合实测 51 和 155 token，按 $20/M 约 $0.001–0.003 每回合 |
| 删减被锁定的人设和内容范围 | 系统块 4359 token（own 的 Q5 实测）里约 3150（估计）被 §7.1–7.5 的基线和内容范围的哈希锁定。每 1000 token 没命中缓存约省 $0.005，命中约 $0.0002（估计）。要你明确同意，还会改人设 |
| 压缩 JSON 键名（历史改成 `[who,text]`） | 每条约 4–6 token，40 条约 $0.0007 每回合（估计）。改的是 `AGENTS.md` 写明、测试钉住的防注入框架，不值得 |
| 判定调用的各种微调 | 判定提示词缓存、降判定上限、缩判定输入、`max_tokens` 改 80、跳过后退避：缓存每次约省 678 × $0.09/M ≈ $0.00006，上限每天最多约 $0.04（估计）。每项都要改代码和测试，钱太少 |
| 合并多个 @，或用固定回复 | 违反 §5.2（真实 @ 不合并）和 §8.4（@ 和被判定为对她说话的点名交给模型），也违反“固定句不改也不加”的决定 |
| 随机插话 | §5.3 禁止用随机抽中代替相关性判断 |
| 预测会不会命中缓存，不命中时去掉缓存标记 | 每次真没命中约省 $0.0044（估计），但命不命中取决于别的群，预测不了，还改“只放一个 5 分钟标记”的决定。有第 1 项的数据再看 |
| 流式输出，中途中止 | 决定里写了第一版不用流式，要先有付费探测证明中止的请求怎么计费 |

Q5 探测本身考虑过、又放弃的做法（`max_tokens` 300–600、按 $8/$30 算、两个静态回合、保留判定或直连调用）记在 [DECISIONS.md](../DECISIONS.md) 的“用户定的（2026-11-06，Q5 和费用）”。
